# API Mira для веб-чата `/chat` и Telegram Mini App

Один бэкенд на два входа. Все запросы `POST` с JSON, ответы JSON. Адрес задаёт сайт (например `https://api.mira-calm.ru`), CORS открыт только для `ALLOWED_ORIGINS`.

## 1. Сессия: `POST /v1/session`

Вызывается при открытии страницы.

| Где открыта страница | Тело запроса |
|---|---|
| Внутри Telegram (`window.Telegram.WebApp.initData` не пустой) | `{ "channel": "tg", "initData": Telegram.WebApp.initData }` |
| На сайте | `{ "channel": "web", "token": "<из localStorage или не передавать>" }` |

Ответ `200`: `{ "token": "…", "consented": true|false }`. Токен сохранить (на сайте в `localStorage`) и слать в `Authorization: Bearer <token>` во всех остальных запросах.
`consented: false` → показать ворота (AI, 18+, согласие). В Telegram согласие общее с ботом: кто согласился в чате бота, в Mini App ворота не видит.
Ошибки: `401 bad_init_data` (подпись Telegram не сошлась или устарела, больше 24 ч), `429 rate_limited`.

## 2. Согласие: `POST /v1/consent`

Тело: `{ "adult": true, "health": true }` (обе галочки ворот). Ответ `200`: `{ "text": "первая реплика Mira" }`. Иначе `400 consent_required`.

## 3. Сообщение: `POST /v1/chat`

Тело: `{ "text": "…" }` (до 2000 символов, длиннее обрежется с пометкой в ответе). Ответ `200`:

```json
{ "text": "ответ Mira", "crisis": false, "needConsent": false, "error": false }
```

- `crisis: true` → кризисный режим из ux-logic §3.6: закрепить карточку с номерами над полем ввода до конца сессии, облачко без анимации. Номера уже есть в `text`, но карточка нужна отдельно.
- `needConsent: true` → сессия потеряла согласие (сервер перезапускался), снова показать ворота.
- `error: true` → модель недоступна, `text` содержит вежливое извинение, можно показать как обычное сообщение.
- История хранится на сервере, клиент шлёт только новое сообщение.

## 4. Забыть разговор: `POST /v1/reset`

Тело `{}`. Ответ `{ "text": "…" }`. Для пункта меню «Удалить мои данные» (сейчас кроме переписки и согласия в памяти ничего нет).

## 5. Оценка сессии: `POST /v1/rating`

Тело: `{ "score": 1..5 }`. Ответ `{ "ok": true }`. Сервер хранит только счётчики по баллам, без привязки к человеку.

## Прочее

- `GET /health` → `{ "ok": true }`.
- Ошибки всегда `{ "error": "<код>" }`: `400 bad_request`, `401 unauthorized`, `403 forbidden` (чужой Origin), `404 not_found`, `413` (тело больше 16 КБ), `500 internal`.
- Перезапуск сервера: токены остаются валидными, но переписка и согласие забываются (данные только в памяти).
