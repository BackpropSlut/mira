# API Mira для веб-чата `/chat` и Telegram Mini App

Один бэкенд на два входа. Все запросы `POST` с JSON, ответы JSON. Адрес задаёт сайт (например `https://api.mira-calm.ru`), CORS открыт только для `ALLOWED_ORIGINS`.

## 1. Сессия: `POST /v1/session`

Вызывается при открытии страницы.

| Где открыта страница | Тело запроса |
|---|---|
| Внутри Telegram (`window.Telegram.WebApp.initData` не пустой) | `{ "channel": "tg", "initData": Telegram.WebApp.initData }` |
| На сайте | `{ "channel": "web", "token": "<из localStorage или не передавать>" }` |

Ответ `200`: `{ "token": "…", "consented": true|false }`. Токен сохранить (на сайте в `localStorage`) и слать в `Authorization: Bearer <token>` во всех остальных запросах.
`consented: false` → показать ворота (AI, 18+, согласие). В Telegram согласие общее с ботом: кто согласился в чате бота, в Mini App ворота не видит.
Ошибки: `401 bad_init_data` (подпись Telegram не сошлась или устарела, больше 24 ч), `429 rate_limited`.

## 2. Согласие: `POST /v1/consent`

Тело: `{ "adult": true, "health": true }` (обе галочки ворот). Ответ `200`: `{ "text": "первая реплика Mira" }`. Иначе `400 consent_required`.

## 3. Сообщение: `POST /v1/chat`

Тело: `{ "text": "…" }` (до 2000 символов, длиннее обрежется с пометкой в ответе). Ответ `200`:

```json
{ "text": "ответ Mira", "risk": "none", "crisis": false, "needConsent": false, "error": false }
```

- `risk: "acute"` / `crisis: true` (одно и то же, `crisis` оставлен для совместимости) → реальная угроза: показать и закрепить карточку с номерами над полем ввода до конца сессии, облачко без анимации. Карточку **не** показывать при `risk: "none"`, даже если человеку грустно или тревожно.
- Когда включается `acute`: явная кризисная фраза (мысли о смерти, самоповреждение, насилие; модель не вызывается, ответ заготовлен) или модель сама оценила риск по смыслу разговора, как это делают Claude и ChatGPT. Паника, стресс, слёзы без мыслей о смерти: `none`, Mira поддерживает сама.
- После `acute` флаг держится до `/v1/reset` или до долгой паузы.
- `needConsent: true` → согласия нет (например, токен от другой базы), снова показать ворота.
- `error: true` → модель недоступна, `text` содержит вежливое извинение, можно показать как обычное сообщение.
- История хранится на сервере, клиент шлёт только новое сообщение.

## 4. Забыть разговор: `POST /v1/reset`

Тело `{}`. Ответ `{ "text": "…" }`. Забывает разговор и сохранённую историю, согласие и тариф остаются.

### Удалить мои данные: `POST /v1/forget`

Тело `{ "confirm": true }` (без него `400 confirm_required`: страница сначала спрашивает «точно?»). Ответ `{ "text": "…", "consented": false }`. Удаляет разговор, сохранённую историю и согласие; после этого `/v1/chat` снова вернёт `needConsent`. Тариф и активированный код остаются. То же в боте: команда `/delete` с кнопками «да / нет».

## 5. Оценка сессии: `POST /v1/rating`

Тело: `{ "score": 1..5 }`. Ответ `{ "ok": true }`. Сервер хранит только счётчики по баллам, без привязки к человеку.

## 6. Тарифы

Правила (решение Петра 15.10):

| | Бесплатно | Премиум |
|---|---|---|
| Текст | до `FREE_TEXT_PER_DAY` сообщений в сутки по МСК (по умолчанию 15) | без лимита |
| Голос | скрытый пробный: `FREE_VOICE_TRIAL` голосовых ответов (по умолчанию 5), счётчика в интерфейсе нет | без лимита |
| История | только текущий разговор, на диск не пишется | сохраняется, `GET /v1/history` |
| Кризис (`risk: acute`), сильный дистресс, номера помощи | **всегда, без лимитов**, голосом тоже | то же |

Премиум сейчас даётся только кодами тестеров (`MIRA-TEST-XXXXXX`, выдаются на сервере `npm run codes`). Оплата (Telegram Stars, ЮKassa) позже.

- `POST /v1/session` дополнительно возвращает `plan: "free" | "premium"` и `premiumUntil: ISO | null`.
- `POST /v1/redeem` `{ "code": "MIRA-TEST-ABC123" }` → `200 { plan, premiumUntil }`. Регистр, пробелы и русские буквы в коде не важны. Ошибки: `400 bad_code` (нет такого или отозван), `400 used_code` (активировал другой человек), `429 rate_limited` (больше 10 попыток в час). Свой же код повторно: `200`.
- `POST /v1/chat` принимает `voice: "f" | "m" | "off"` (по умолчанию `off`) и дополнительно возвращает:
  - `voice: { url } | null`: ссылка на голосовой ответ, живёт час, открывается без токена (для `<audio>`). Пока синтеза нет, всегда `null`.
  - `limit: "voice" | "text" | null`. `voice` приходит **один раз**, на первом ответе после конца пробного голоса: можно мягко показать премиум. `text` значит, что дневной лимит исчерпан и модель не отвечала: в `text` уже вежливое сообщение.
- `GET /v1/history` (Bearer) → `200 { messages: [{ role: "user" | "assistant", text, ts }] }`, последние 200. Бесплатный тариф: `403 premium_required`.
- `POST /v1/reset` удаляет и сохранённую историю. Тариф не трогает.
- В Telegram-боте код вводится командой `/code MIRA-TEST-ABC123`. Тариф общий для бота и Mini App.

## Прочее

- `GET /health` → `{ "ok": true }`.
- Ошибки всегда `{ "error": "<код>" }`: `400 bad_request`, `401 unauthorized`, `403 forbidden` (чужой Origin), `404 not_found`, `413` (тело больше 16 КБ), `500 internal`.
- Перезапуск сервера: токены, согласие, тариф и история премиума сохраняются (SQLite на сервере). Текущий разговор бесплатного тарифа забывается.
